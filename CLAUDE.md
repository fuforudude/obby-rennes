# Obby Rennes : « Partiel maintenu »

Obby Roblox pour étudiants : traverser Rennes (fac bloquée, métro en grève, cortège, barricades de poubelles, rue de la Soif, Vilaine, Parlement, Thabor) pour arriver à l'heure au partiel à Sup de Vinci. Ton : satire du quotidien étudiant, sans prendre parti (pas de police, pas de slogan politique réel). Game design : `docs/game-design.md`.

## Jeu Roblox
- Code Luau dans `src/` (`serveur/`, `client/`, `partage/`), synchronisé dans Studio par Rojo (`rojo serve`). Studio n'est jamais la source du code : une modification faite dans Studio est perdue si elle n'est pas reportée dans `src/`.
- Cartes et décors dans `monde/` (fichiers .rbxm), générés par les scripts Lune de `outils/monde/` ; `outils/monde/monde.json` dit qui en est l'auteur. Une carte retouchée à la main dans Studio (« auteur » : « utilisateur ») n'est plus jamais régénérée.
- Tests TestEZ dans `tests/` (`*.spec.luau`), absents de la version publiée.
- **Tout vérifier** : `lourd node outils/tout-verifier.mjs`, la commande que lance la CI (détail plus bas). `roblox verifier` ne fait que format, lint et construction Rojo : ni types, ni tests, ni contrôles de carte. `roblox tests` (tests dans le cloud, place de test), `roblox publier test`. `roblox publier prod` seulement avec l'accord explicite de l'utilisateur.
- Places : `.claude/roblox.json`. Historique des publications : `docs/publications.md`.

## Repères du code
- Contrats carte ↔ serveur (tags et attributs posés par `outils/monde/Parcours.luau`) : `Checkpoint` + `Numero` (l'ensemble des `Numero` est exactement 0..`Reglages.NB_ETAPES`), `Mortel`, `Fragile`, `Mobile` + `Deplacement`/`Duree`, `Tournant` + `Vitesse`, `TableauClassement`, `TableauAura`, `DeblocageCapacite` + `Capacite`. La liste complète des tags que le jeu lit (tour comprise) est `TAGS_CONNUS` dans `outils/monde/verifier-contrats.luau` : un tag posé sur une carte et absent de cette liste fait échouer le contrôle. Nouveau tag = l'ajouter là, avec le fichier qui le lit.
- Tour (`outils/monde/Ascension.luau`) : une entrée de `segments` par tranche (couleur, difficulté, portes, familles d'obstacles ; `NB_TRANCHES = #segments`). Nouvelle famille de piège = un poseur dans le registre `poseurs` d'`Ascension.luau` (une famille sans poseur fait échouer la génération), un simulateur dans le registre `FAMILLES` de `verifier-ascension.luau` (un tag de la tour sans simulateur fait échouer le contrôle), son tag dans `TAGS_CONNUS`.
- Contrats carte ↔ jeu des événements (posés par `outils/monde/Evenements.luau`, détail en tête de ce fichier et dans `docs/specs/2026-11-13-evenements-batiments-interface.md`) :
  - `Evenement` sur un Model (PrimaryPart = son pivot) : attributs `Type` (« Passage » ou « Chute »), `Periode`, `Decalage` (instant où le danger commence), `Preavis` ; Passage : `Depart`, `Arrivee`, `DureePassage` ; Chute : `Hauteur`, `DureeChute`. Enfant facultatif `Preavis` (BasePart : ombre, phares), laissé à sa place posée. Pièces ancrées, sans collision ni toucher.
  - `Balancier` sur une BasePart ancrée au repos : `Pivot`, `Axe`, `Amplitude` (degrés), `Periode`, `Decalage` ; `ZoneControleMin`/`ZoneControleMax` ne servent qu'aux contrôles. Le serveur (`src/serveur/Obstacles/Balancier.luau`) le fait osciller (`Horaires.angleBalancier`) : il pousse, il ne tue pas.
  - `PanneauAnecdote` + `Numero` (0 à `NB_ETAPES`) : SurfaceGui avec deux TextLabel, `Titre` (la zone) et `Corps` (l'anecdote puis la vanne du checkpoint), écrits par le client (`src/client/Interface/Panneaux.luau`).
- Événements, principe : chaque client anime les objets taggés `Evenement` d'après `workspace:GetServerTimeNow()` (`src/client/Evenements.luau`), tient à jour pièces et `Preavis` quand le streaming les amène ou les retire, et voit le contact avec son personnage. Il le signale par le remote `ToucheParEvenement(objet: Instance)` ; le serveur (`src/serveur/Evenements.luau`) valide (type, tag, attributs, joueur vivant, danger actif à la tolérance près, joueur près de la trajectoire, signalements espacés) puis tue le joueur, ce qui passe par `Humanoid.Died` et le décompte de chute de `Parcours.luau`. La règle de validation est pure et testée : `src/partage/Signalement.luau`.
- Règles pures et testées : `src/partage/Regles.luau`. Horaires des événements (cycle actif/attente/préavis, tolérance, balancier, lecture des attributs) : `src/partage/Horaires.luau`. Mise en forme de ce que l'interface affiche (étape, chrono, aura, texte des panneaux, résumé d'arrivée) : `src/partage/Affichage.luau`. Étapes et anecdotes : `src/partage/Etapes.luau`. Réglages (dont l'identifiant du produit « Passer l'étape » et les `EVENEMENT_*`) : `src/partage/Reglages.luau`.
- Contrôles de carte (après `generer.luau`, code de sortie 1 au moindre défaut ; tous lancés par `outils/tout-verifier.mjs`) : `verifier-contrats.luau` (tags connus, checkpoints 0..`NB_ETAPES` sans trou ni doublon, sur toutes les cartes de `monde.json`), `verifier-sauts.luau` (tuto : chaque checkpoint atteignable, portes de capacité strictement nécessaires), `verifier-evenements.luau` (attributs cohérents, fenêtre sûre d'au moins 2 s sur chaque plateforme touchée, fenêtre de passage des balanciers, panneaux d'anecdote), `verifier-ascension.luau` (tour : les trois capacités exigées, fenêtres de passage des obstacles, accès, étages). Ils ne recopient rien : `NB_ETAPES`, `COURSE_FACTEUR` et le modèle prudent du saut (bloc `CONTROLE_*`) sont lus dans `src/partage/Reglages.luau`, la physique et le masque des capacités dans `outils/monde/physique.luau`, le nombre de tranches de la tour sur la carte (dalles `Pas<tranche>_<rang>`) ; un dossier de zone du tuto se reconnaît au motif `^%d+_`.
- Cartes cassées (`outils/monde/casser-parcours.luau`, `casser-ascension.luau`, `casser-contrats.luau`) : chaque panne fabrique une carte fautive qui doit faire échouer son contrôle avec un message précis ; la liste (panne, contrôle, message attendu) est dans `outils/tout-verifier.mjs`. Un nouveau contrôle s'y ajoute avec sa carte cassée.
- Empreinte des cartes : `lune run outils/monde/empreinte.luau <sortie.txt> [fichiers ou dossiers]` (défaut : `monde/`), une ligne triée par instance (chemin, classe, position, rotation, taille, couleur, matériau, collision, texte, tags, attributs ; arrondis à 0,01). Pour prouver qu'une refonte d'un générateur ne change pas la carte : empreinte avant, empreinte après, `git diff --no-index` ; toute différence voulue va dans le message de commit.
- Mode vol des testeurs (touche F, spec `docs/specs/2026-11-19-mode-vol-testeurs.md`) : liste `Reglages.TESTEURS` (`[identifiant] = true`), décision pure `src/partage/Vol.luau`, service `src/serveur/Vol.luau` (seul juge ; remotes `DemanderVol` / `EtatVol`), mouvement `src/client/Vol.luau`. Un vol marque la course (`Course.vol` : non classable, aura figée, jusqu'à « Recommencer »), la tentative d'ascension le lit par `Parcours.aVole`, et la surveillance (`Capacites.mesurer`, `entrerVol` / `sortirVol`) se réamorce à chaque relevé en vol puis sur la position de sortie.
- Données des joueurs : `src/serveur/Donnees.luau` (ProfileStore, ADR 0001). Classement : `src/serveur/Classement.luau`. Achats : `src/serveur/Boutique.luau`.
- Anecdotes sur Rennes : uniquement des faits vérifiables ; pas de logo officiel de Sup de Vinci sans accord de l'école.

## CI et publication
- `.github/workflows/verifier.yml` : check `verifier` sur chaque PR vers `main` (et appelé par `publier.yml`). Sans secret. Installe les outils de `rokit.toml` (action locale `.github/actions/outils`), `wally install`, la bibliothèque standard Roblox de Selene, puis lance `node outils/tout-verifier.mjs`, qui enchaîne et s'arrête au premier échec en disant lequel : `stylua --check src tests outils`, `selene src`, `node outils/analyser-types.mjs` (types Luau par luau-lsp sur `src/partage`, `src/serveur` et `src/client` ; la liste `A_TRAITER` du script est vide, ne jamais y ajouter un fichier), `node --test outils/publier.test.mjs`, tests Lune (`outils/tests/lancer-specs.luau`), génération de la carte et **carte commitée = carte générée** (la génération est déterministe : tout octet changé dans `monde/` est un échec, sauf si l'empreinte arrondie est identique, cas d'un écart flottant entre machines, accepté avec un avertissement), les quatre contrôles de carte, les cartes cassées (environ 35 s en local), `rojo build`. Environ une minute en local.
- `.github/workflows/publier.yml` : à chaque push sur `main` (donc après fusion) : `verifier`, puis `construire` (artefact `jeu-rbxl`), puis `publier-test` (environnement GitHub `test`, expérience de test, automatique), puis `publier-prod` (environnement GitHub `production`, derrière approbation). `construire` régénère la carte et relance tous les contrôles de carte et les cartes cassées (`node outils/tout-verifier.mjs --cartes`) avant `rojo build` : la carte publiée est la carte vérifiée, et un contrôle rouge bloque test comme production. Le même fichier `jeu.rbxl` va en test puis en production. Chaque cible a son groupe de concurrence (`publier-test`, `publier-prod`), jamais annulé.
- La publication se fait par la CI après fusion sur `main` : plus de publication manuelle depuis Studio. Deux clés Open Cloud, une par expérience : chacune est le secret `ROBLOX_API_KEY` de **son environnement** GitHub (`test` ou `production`, limités à la branche `main`), jamais un secret du dépôt. Les identifiants des places de `.claude/roblox.json` (s'ils valent 0, le job s'arrête avec un message).
- Approuver la production : onglet Actions du dépôt, ouvrir l'exécution « Publier », « Review deployments », cocher `production`, « Approve and deploy ». Sans approbation, rien n'est publié en production.
- Version publiée : résumé de l'exécution (numéro de version Roblox et commit), pour `publier-test` et `publier-prod`.
- Équivalent local du check : `lourd node outils/tout-verifier.mjs` (la même commande ; `--cartes` pour la seule partie carte). Elle régénère `monde/` : une carte pas à jour est réécrite et signalée, à commiter.
