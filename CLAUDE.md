# Obby Rennes : « Partiel maintenu »

Obby Roblox pour étudiants : traverser Rennes (fac bloquée, métro en grève, cortège, barricades de poubelles, rue de la Soif, Vilaine, Parlement, Thabor) pour arriver à l'heure au partiel à Sup de Vinci. Ton : satire du quotidien étudiant, sans prendre parti (pas de police, pas de slogan politique réel). Game design : `docs/game-design.md`.

## Jeu Roblox
- Code Luau dans `src/` (`serveur/`, `client/`, `partage/`), synchronisé dans Studio par Rojo (`rojo serve`). Studio n'est jamais la source du code : une modification faite dans Studio est perdue si elle n'est pas reportée dans `src/`.
- Cartes et décors dans `monde/` (fichiers .rbxm), générés par les scripts Lune de `outils/monde/` ; `outils/monde/monde.json` dit qui en est l'auteur. Une carte retouchée à la main dans Studio (« auteur » : « utilisateur ») n'est plus jamais régénérée.
- Tests TestEZ dans `tests/` (`*.spec.luau`), absents de la version publiée.
- `roblox verifier` (format, lint, construction), `roblox tests` (tests dans le cloud, place de test), `roblox publier test`. `roblox publier prod` seulement avec l'accord explicite de l'utilisateur.
- Places : `.claude/roblox.json`. Historique des publications : `docs/publications.md`.

## Repères du code
- Contrats carte ↔ serveur (tags et attributs posés par `outils/monde/Parcours.luau`) : `Checkpoint` + `Numero`, `Mortel`, `Fragile`, `Mobile` + `Deplacement`/`Duree`, `Tournant` + `Vitesse`, `TableauClassement`.
- Contrats carte ↔ jeu des événements (posés par `outils/monde/Evenements.luau`, détail en tête de ce fichier et dans `docs/specs/2026-11-13-evenements-batiments-interface.md`) :
  - `Evenement` sur un Model (PrimaryPart = son pivot) : attributs `Type` (« Passage » ou « Chute »), `Periode`, `Decalage` (instant où le danger commence), `Preavis` ; Passage : `Depart`, `Arrivee`, `DureePassage` ; Chute : `Hauteur`, `DureeChute`. Enfant facultatif `Preavis` (BasePart : ombre, phares), laissé à sa place posée. Pièces ancrées, sans collision ni toucher.
  - `Balancier` sur une BasePart ancrée au repos : `Pivot`, `Axe`, `Amplitude` (degrés), `Periode`, `Decalage` ; `ZoneControleMin`/`ZoneControleMax` ne servent qu'aux contrôles. Le serveur (`src/serveur/Obstacles.luau`) le fait osciller (`Horaires.angleBalancier`) : il pousse, il ne tue pas.
  - `PanneauAnecdote` + `Numero` (0 à 15) : SurfaceGui avec un TextLabel `Texte` ; le client y écrit la zone, l'anecdote et la vanne du checkpoint (`src/client/Interface/Panneaux.luau`).
- Événements, principe : chaque client anime les objets taggés `Evenement` d'après `workspace:GetServerTimeNow()` (`src/client/Evenements.luau`), tient à jour pièces et `Preavis` quand le streaming les amène ou les retire, et voit le contact avec son personnage. Il le signale par le remote `ToucheParEvenement(objet: Instance)` ; le serveur (`src/serveur/Evenements.luau`) valide (type, tag, attributs, joueur vivant, danger actif à la tolérance près, joueur près de la trajectoire, signalements espacés) puis tue le joueur, ce qui passe par `Humanoid.Died` et le décompte de chute de `Parcours.luau`. La règle de validation est pure et testée : `src/partage/Signalement.luau`.
- Règles pures et testées : `src/partage/Regles.luau`. Horaires des événements (cycle actif/attente/préavis, tolérance, balancier, lecture des attributs) : `src/partage/Horaires.luau`. Mise en forme de ce que l'interface affiche (étape, chrono, aura, texte des panneaux, résumé d'arrivée) : `src/partage/Affichage.luau`. Étapes et anecdotes : `src/partage/Etapes.luau`. Réglages (dont l'identifiant du produit « Passer l'étape » et les `EVENEMENT_*`) : `src/partage/Reglages.luau`.
- Contrôles de la carte des événements : `lune run outils/monde/verifier-evenements.luau` (après `generer.luau`) : attributs cohérents, fenêtre sûre d'au moins 2 s sur chaque plateforme touchée, fenêtre de passage des balanciers, panneaux d'anecdote (numéros, texte, position). Code de sortie 1 au moindre défaut.
- Données des joueurs : `src/serveur/Donnees.luau` (ProfileStore, ADR 0001). Classement : `src/serveur/Classement.luau`. Achats : `src/serveur/Boutique.luau`.
- Anecdotes sur Rennes : uniquement des faits vérifiables ; pas de logo officiel de Sup de Vinci sans accord de l'école.

## CI et publication
- `.github/workflows/verifier.yml` : check `verifier` sur chaque PR vers `main` (et appelé par `publier.yml`). Sans secret. Installe les outils de `rokit.toml` (action locale `.github/actions/outils`), puis `wally install`, `stylua --check src tests outils`, `selene src`, `node --test outils/publier.test.mjs`, tests Lune (`outils/tests/lancer-specs.luau`), génération de la carte et vérification des sauts, `rojo build`.
- `.github/workflows/publier.yml` : à chaque push sur `main` (donc après fusion) : `verifier`, puis `construire` (artefact `jeu-rbxl`), puis `publier-test` (environnement GitHub `test`, expérience de test, automatique), puis `publier-prod` (environnement GitHub `production`, derrière approbation). `construire` régénère la carte (`generer.luau`) avant `rojo build` : la carte publiée est la carte vérifiée. Le même fichier `jeu.rbxl` va en test puis en production. Chaque cible a son groupe de concurrence (`publier-test`, `publier-prod`), jamais annulé.
- La publication se fait par la CI après fusion sur `main` : plus de publication manuelle depuis Studio. Deux clés Open Cloud, une par expérience : chacune est le secret `ROBLOX_API_KEY` de **son environnement** GitHub (`test` ou `production`, limités à la branche `main`), jamais un secret du dépôt. Les identifiants des places de `.claude/roblox.json` (s'ils valent 0, le job s'arrête avec un message).
- Approuver la production : onglet Actions du dépôt, ouvrir l'exécution « Publier », « Review deployments », cocher `production`, « Approve and deploy ». Sans approbation, rien n'est publié en production.
- Version publiée : résumé de l'exécution (numéro de version Roblox et commit), pour `publier-test` et `publier-prod`.
- Équivalent local du check : `lourd roblox verifier`, puis `lune run outils/tests/lancer-specs.luau`, `lune run outils/monde/generer.luau` et `lune run outils/monde/verifier-sauts.luau`.
